# 乐学公网服务安全检查

检查日期：2026-10-11（北京时间）  
部署地址：https://ai.liqi123.com/lexue/  
本地代码基线：主分支 `c8e65a6`，包括检查时已有的未提交文件。

## 1. 结论

**已有鉴权、限流和每日额度，但付费生成服务目前仍存在被批量使用、消耗费用及拖垮服务的风险。建议先修复高风险项，再向大众无门槛开放 AI 生成和故事配音。**

不需要泄漏供应商 API Key 才能产生费用：外部用户可以通过公开的访客会话和注册流程，调用应用提供的付费能力；故事配音还有独立于普通朗读接口的额度与并发缺口。OSS 文件虽然需要签名，但内置故事签名入口本身公开，签名链接可以用于直接访问 OSS，绕开应用端的调用计数。

本次进行了代码审查、6 项离线复现，以及少量线上请求。没有进行线上压测、批量注册、密码猜测、家庭数据读取或实际 AI/语音生成任务；语音和 AI 的匿名请求均在鉴权阶段被拒绝。OSS 仅通过范围请求成功读取了现有音频的 1 字节。线上测试产生了一条带 `owner-security-audit-` 前缀的访客设备记录，没有创建家长账号。

## 2. 已有保护

以下数值为**代码默认值，不是已核实的服务器实际配置**；环境变量及数据库中的家庭额度可覆盖它们。

| 能力 | 默认限制 | 说明 |
| --- | --- | --- |
| 普通在线朗读 `/api/tts` | 每设备/家庭 30 次/分钟；每 IP 60 次/分钟 | 需要有效访客或账号 Token |
| 普通在线朗读进程级限制 | 同时 3 个请求；全进程 60 次/分钟 | 尚未鉴权的请求也占用这一限制 |
| 普通在线朗读每日额度 | 访客每设备 30 次；家庭 300 次 | 依赖数据库；成功后记账 |
| TTS 上游全站每日额度 | 5,000 次 | 仅计数成功记录的上游调用，并非金额上限 |
| AI 新增资料 `/api/content/generate` | 每家庭 5 次/分钟；每 IP 10 次/分钟；家庭 20 次/日 | 访客不可调用；普通接口同时 2 个请求、全进程 20 次/分钟 |
| AI 全站每日额度 | 500 次 | 不是 Token 或金额硬上限；一次新增资料最多会尝试两次模型请求 |
| AI 故事文本生成 | 每家庭 3 篇/日，另检查 AI 用户及全站额度 | 没有接入普通新增资料接口的全进程并发限制 |
| 家庭故事数量 | 每家庭 50 篇未归档故事 | 不是每日配音次数限制，也不是磁盘容量限制 |
| 故事配音任务 | 尝试限制每家庭同时一篇；每篇最多 120 句 | 检查不是原子操作；没有全站队列并发上限 |
| 注册、登录、访客会话 | 每 IP 每 15 分钟分别 10、20、120 次 | IP 来源存在信任问题；计数在进程内存中 |
| 输入大小 | 普通朗读最多 3,000 字符；AI 提示最多 500 字符；故事正文最多 6,000 字符；同步默认 5 MB | 单次限制有帮助，但不能替代次数、并发与资金预算 |

其他已有保护：供应商密钥只在服务端读取；数据库查询使用参数绑定；孩子和家庭故事的大部分接口按家庭校验归属；密码使用 scrypt；Token 使用 HMAC 签名；千问音频下载检查供应商域名并禁用重定向；部署示例将应用端口绑定至本机回环地址。

## 4. 高风险发现

### 4.1 故事配音绕过用户 TTS 额度和普通朗读的并发限制

位置：`server/story-service.mjs:110`、`:196`、`:250`、`:282`。

配音入口仅检查登录、故事归属及另一个家庭任务是否存在，没有调用 `usage.authorize(req, 'tts')`。后台逐句配音只检查全站 TTS 额度，再直接调用 `synthesize`；普通朗读接口的每家庭/IP 限流、每日用户额度、全进程 3 并发和 60 次/分钟不覆盖它。

已离线复现：将统一额度鉴权设置成必定拒绝，配音提交仍返回 202，额度鉴权调用次数为 0。

一个任务最多可以触发 120 次分句处理。用户还可以直接提交故事文字再配音，而不经过每天 3 篇 AI 故事文本生成的限制。多家庭可同时创建任务；每家庭单任务检查是“先查后写”，不同故事的并发提交存在竞争。队列没有全站工作线程上限，完成拼接前还会并行启动多次 ffprobe。重复处理已完成故事即使命中语音缓存，仍可能消耗读写、数据库和音频处理资源。

**建议：**所有配音入口和后台分句都接入同一费用预算；提交时原子预占任务/字数额度；使用有容量上限及固定并发的任务队列；按家庭原子约束活跃任务；为重复配音、重试及手动提交文字分别设置规则。不要把“每家庭最多 50 篇故事”当作每日配音预算。

### 4.2 客户端可以影响 IP 限流身份

位置：`server/http.mjs:36`、`deploy/baota-lexue.conf:13`、`server/identity.mjs:40`、`server/usage.mjs:24`。

`requestIp` 直接取 `X-Forwarded-For` 的第一项。仓库中的 Nginx 模板使用 `$proxy_add_x_forwarded_for`，会保留客户端先提供的值。若线上采用该配置，客户端可以伪造首项，影响注册、登录、访客申请以及 AI/TTS 的 IP 计数。已离线复现首项被接受；没有对线上做绕过压测，也未读取线上 Nginx 完整配置。

**建议：**只信任明确配置的反向代理。单层 Nginx 情况下由入口覆盖转发 IP；有 CDN/WAF 时先配置其可信地址和 real-IP 规则，再由入口写入规范化地址。不能只改应用改读一个同样可伪造的头。

### 4.3 每设备/家庭额度容易通过新身份重新获得

位置：`server/identity.mjs:104`、`:112`、`:132`。

访客 `deviceId` 由客户端提交，可更换后申请新 Token；它不是可信硬件标识。注册只检查邮箱格式和密码长度，没有邮箱所有权验证、邀请码或人机验证。注册成功会得到新的家庭及默认 AI/TTS 额度。线上已确认访客申请可用，注册接口处于有效邮箱校验阶段。

因此，外部脚本无需窃取密钥，就可以反复获得应用赋予的新身份额度。在全站限制起作用时仍可能把全站额度消耗完，导致正常用户无法使用；不能把每日每家庭 20 次 AI、300 次 TTS 当作防批量注册措施。

**建议：**付费功能由已验证且符合准入规则的账号使用；注册、首次使用及异常行为增加人机验证；访客尽量仅使用浏览器朗读、预生成音频或缓存，不提供任意新文本的上游合成。结合可信 IP、账号及全站预算，而不是只依赖 deviceId。

### 4.4 管理员邮箱未验证就能赋予管理员权限

位置：`server/identity.mjs:35`、`:117`、`:130`。

注册时仅根据邮箱是否属于 `ADMIN_EMAILS` 决定 `is_admin`，没有验证用户控制该邮箱。**若配置的管理员邮箱尚未注册，且注册开放，知道该邮箱的人可能先注册并获得管理员权限。**已有同名账号时会被邮箱唯一约束阻止，不能据此认定现有管理员账号已被接管。

离线模拟注册已复现 201 和 `is_admin=true`；没有在线尝试注册管理员或任何其他家长账号，也不知道服务器当前管理员邮箱名单及注册状态。

**建议：**公开注册永远创建普通账号；管理员通过受控流程授予。即使增加邮箱验证，也不要把公开注册表单直接作为管理员创建入口。

### 4.5 每日与全站额度存在并发竞争及失败漏账

位置：`server/usage.mjs:40`、`:45`、`:57`，`server/tts.mjs:187`、`:201`，`server/content-generator.mjs:118`、`:172`，`server/story-service.mjs:240`。

当前是“读取已用额度 → 调用供应商 → 成功后记录”，检查与消耗不是同一个原子操作。离线将每日上限设为 1，并发执行两次检查，两次均被放行，最终记录为 2。全站和每天 3 篇故事也采用相似逻辑；故事后台缺少全站并发限制会放大竞争。

上游失败不记录调用；若供应商已经计费，而后续下载音频、校验模型输出、写缓存或写数据库失败，成本可能没有进入应用账本。AI 新增资料最多重试两次，但成功的业务请求只记 1 次。TTS 以次数而非字数控制成本，同为一次请求，短字词与 3,000 字符的消耗不同。

**建议：**调用前原子预占请求、字符或 Token 预算；将供应商请求次数与业务成功次数分开记录；在 finally 中结算成功、失败和重试；处理超时费用不确定的情况；另外设置供应商侧预算或计费告警。金额限制能力需逐供应商核实。此类问题属于 [OWASP API4 资源消耗风险](https://api-security.owasp.org/editions/2023/en/0xa4-unrestricted-resource-consumption/)。

### 4.6 OSS 私有读取不等于流量已经受到保护

位置：`server/story-service.mjs:207`、`server/story-storage.mjs:21`。

内置音频签名入口在鉴权之前返回 302，没有应用层次数、IP 或流量额度限制，也没有核查文件是否属于实际清单。已在线验证匿名可获取链接并对现有音频读取 1 字节；无签名则 403。这证明对象读取受签名保护，同时也证明外部持链接者可以直接访问 OSS。该访问不经过 `usage.authorize` 或 `usage.record`。

签名有效期约两小时，而且可以重新请求入口取得新链接，因此不是一次性下载凭证。外部批量 GET/Range 请求可能产生 OSS 请求费及出网流量；公开故事本来就允许访问，应以控制费用和异常下载为目标，而非期待签名阻止所有复制。链接中出现 AccessKey ID 与签名不等于泄漏 AccessKey Secret，但有效链接本身是临时访问凭证，报告没有保存它。

**建议：**为签名入口加可信 IP/会话速率与异常检测；只为清单中的内置文件签名；按音频时长与续签机制缩短有效期；为公共静态音频设计 CDN 缓存及流量限制；在 OSS/CDN/云账户设置流量、请求与费用告警。Referer 防盗链只能作为补充，不能代替身份和费用控制。相关机制见 [阿里云预签名 URL 说明](https://www.alibabacloud.com/help/en/oss/user-guide/how-to-obtain-the-url-of-a-single-object-or-the-urls-of-multiple-objects)及[防盗链说明](https://help.aliyun.com/en/oss/user-guide/hotlink-protection)。

### 4.7 未鉴权请求也能占用全站生成服务槽位

位置：`server/tts.mjs:152`、`server/content-generator.mjs:154`。

两个普通生成接口都在读取正文、验证身份前增加进程级次数并占用并发。已离线复现：前 60 个未经登录的 TTS 请求收到 401，但第 61 个收到全站次数用完的 429。这些请求没有调用供应商，却可以影响合法用户；未鉴权或缓慢发送正文的连接也能占用共享并发槽位。

**建议：**由入口先处理匿名/IP 速率和请求超时；在正式占用付费服务的用户或全站并发槽位前完成身份验证、输入校验及额度预占。应用的 AbortController 超时也应覆盖正文读取/数据库等待，而不只是传给外部 fetch。

## 5. 其他风险与需要核实的事项

- **内存限流不共享且不清理旧身份键。** `minuteWindows` 和 `authWindows` 是进程内 Map，重启会清空，多副本各自计算；大量新身份键会增加内存占用。需要共享计数、过期清理和规模上限。
- **退出不撤销已发出的 Token。** `/api/auth/logout` 只返回成功，客户端删除 localStorage；已经复制的 Token 仍能在有效期内使用，账号 Token 默认 14 天。可增加会话表、撤销或版本机制，结合较短的访问令牌有效期。
- **家庭音频使用 public 长缓存。** `server/story-storage.mjs:29` 对家庭音频和公共故事都写入一年 public Cache-Control，不利于撤销家庭私人音频的访问。家庭文件应采用适当的私有/短缓存策略，公共内置音频再单独配置。
- **磁盘、数据库和 CPU 缺少明确总量预算。** 语音缓存和失败任务目录没有容量/生命周期清理；孩子档案数及同步写入频率没有限制；归档故事仍保留数据库记录。Compose 示例没有 CPU、内存和进程数限制，也没有显式非 root 用户。上线前应配合资源配额、缓存回收、任务保留策略和备份。
- **日期边界可能不一致。** 额度读取用数据库 `current_date`，记录日期用应用 UTC 日期。若数据库时区不是 UTC，会有不一致的计数窗口。需统一业务日期；未查看生产数据库时区。
- **安全头尚可补齐。** 线上有 HTTPS/HSTS/nosniff，但本次首页未发现 CSP、X-Frame-Options 或 CSP frame-ancestors。Token 存在 localStorage，应加强内容来源和防脚本注入；没有在代码中发现直接使用 dangerouslySetInnerHTML 的入口。
- **错误响应可直接带内部错误文本。** 部分身份及故事接口返回 error.message，可能暴露供应商、数据库或 ffmpeg 错误细节。对外统一错误码，对内保留详细日志。
- **本地开发接口保护较弱。** `server/local-services.mjs` 的 AI 中间件没有传入 usage 服务；开发/预览命令监听 0.0.0.0。不要将这些环境暴露公网或让其使用生产凭据。线上目前观察到鉴权行为，但没有读取实际启动命令。
- **生产依赖漏洞查询。** 本次 `pnpm audit --prod` 从官方漏洞库返回已知漏洞数量为 0。这不是业务逻辑安全证明，也不覆盖系统、镜像和宝塔组件。
- **前次检查的 OSS 密钥残留仍需处理。** 本地不可达 Git 对象中的 OSS 凭据与当前本地配置一致。其是否仍被生产使用未核实，详见同目录的《开源前凭据安全检查-2026-10-11》。

## 6. 建议处理顺序

1. 先关闭公开注册自动成为管理员的路径；确认当前管理员名单与身份。
2. 将付费 AI/新音频生成限制给受控账号，保留公众访问学习内容和已有音频的能力。
3. 统一代理 IP 信任、入口限流、正文超时和生成接口鉴权顺序。
4. 为所有供应商调用增加原子预算预占及完整结算；统一普通朗读与故事配音的额度；建立有限并发的后台队列。
5. 为 OSS 公共音频建立签名分发、CDN 流量与费用控制，随后补齐缓存回收、会话撤销及资源限制。
