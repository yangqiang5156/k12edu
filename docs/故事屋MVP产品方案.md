# 故事屋 MVP 产品方案

## 1. 文档信息

- 产品：乐学
- 功能：故事屋
- 适用端：手机 PWA
- 目标用户：3–12 岁儿童及其家长
- 版本范围：MVP
- 文档状态：已确认，进入实现
- 更新日期：2026-09-23

## 2. 背景与产品判断

乐学已经具备儿童年龄设置、在线语音、音频缓存、内容库、学习记录、家庭账号和家长中心。故事能力可以复用这些基础设施，但产品定位与“每日学习任务”不同：学习任务强调练习、完成和掌握，故事强调陪伴、兴趣和自主选择。

因此，MVP 将“故事屋”设计为独立功能，不加入现有 `ModuleId`，不进入六大学习模块的每日排课、间隔复习和模块完成奖励。这样可以减少对现有学习逻辑的影响，也便于先验证儿童是否愿意主动收听。

## 3. 产品目标

### 3.1 用户目标

儿童能够在少量操作内找到适龄故事，稳定收听，并在下次继续上次进度；家长能够控制内容范围和收听时间，了解孩子听过什么。

### 3.2 业务与产品目标

1. 上线后 4 周内，至少 30% 的活跃家庭使用过故事屋。
2. 已开始故事的平均完整收听率达到 60% 以上。
3. 使用过故事屋的家庭中，7 日内再次收听比例达到 35% 以上。
4. 单个故事的重复上游语音合成率接近 0，避免长文本重复产生费用。

以上数值是首版建议目标，上线后应根据实际活跃家庭数校准。

## 4. MVP 范围

### 4.1 本期包含

- 独立的故事屋入口和故事列表。
- 按儿童年龄自动推荐，并支持按阶段、主题和时长筛选。
- 40 篇内置故事，覆盖幼儿园、小学低年级和小学高年级。
- 故事详情及播放器：播放、暂停、前后 15 秒、倍速、进度保存、继续播放。
- 长版音频逐句切片制作，记录真实起止时间；播放、拖动和续听时高亮正在朗读的句子。
- 睡眠定时：听完本篇、10 分钟、20 分钟。
- 收藏、最近收听和收听历史。
- 单篇听到 80% 后记为完成。
- 家长设置每日时长、自动连播、隐藏主题或单篇故事。
- 家长查看近 7 天收听时长、听过的故事和完成情况。
- 预生成音频并复用现有 OSS 能力，正文保留分段结构。
- 故事数据随本地备份及家庭云备份保存。

### 4.2 本期不包含

- AI 实时生成个性化故事。
- 儿童自由输入提示词生成内容。
- 真人录音、角色配音和复杂背景音乐。
- 正式测验、掌握度评估和间隔复习。
- 家长编辑正文或自行生成音频。
- 故事社区、评论、排行榜和公开分享。
- 将故事加入六大学习模块、每日清单或周学习达标计算。

## 5. 信息架构

### 5.1 儿童端入口

首页在学习伙伴之后、今日学习清单之前增加“故事时间”卡片：

- 未收听过：展示“今天想听什么故事？”和 1 篇适龄推荐。
- 有未听完故事：优先展示“继续听”，显示标题和剩余时间。
- 当日达到家长时长限制：显示“今天的故事时间完成啦”，不继续推荐播放。

底部导航仍保持“今日／成长／兑换”三个入口，避免为单一功能增加第四个一级导航。故事屋从首页进入，使用独立 Hash 路由：`#/stories`、`#/stories/:id`。

### 5.2 页面结构

```text
首页故事卡片
    ↓
故事屋
    ├── 继续收听
    ├── 适合当前年龄
    ├── 睡前故事
    ├── 最近收听
    └── 全部故事（阶段／主题／时长筛选）
            ↓
        故事详情
            ↓
        播放器
            ↓
        听完反馈（喜欢／再听一次／返回故事屋）
```

### 5.3 家长端入口

家长中心“任务”页新增“故事设置”，但不列入“开启的学习模块”；“历史”页新增“故事收听”子区块。

## 6. 分龄与内容策略

| 阶段 | 建议年龄 | 单篇时长 | 内容特征 | 主要主题 |
|---|---:|---:|---|---|
| 幼儿园 | 3–6 岁 | 3–6 分钟 | 单线情节、重复句式、角色少、结尾明确 | 动物、生活习惯、情绪、安全、友情 |
| 小学低年级 | 6–9 岁 | 6–10 分钟 | 完整起承转合，可理解简单因果和寓意 | 寓言、成语、神话、自然、人物 |
| 小学高年级 | 9–12 岁 | 10–15 分钟 | 情节更丰富，允许多角色和价值讨论 | 历史、名著、科学、成长、冒险 |

年龄是默认推荐依据，不是硬性隔离。儿童可查看相邻阶段，家长隐藏的内容除外。

### 6.2 内容质量规则

- 幼儿园正文尽量使用短句，每段不超过 80 个汉字。
- 小学故事出现生僻词时，在字幕中提供简短释义。
- 不使用惊吓式音效，不渲染暴力细节，不包含商业引导。
- 安全故事必须给出清晰可执行的做法，不把责任归咎于儿童。
- 每篇故事配置一句简介、1–3 个主题、适龄范围和预计时长。
- 每篇故事都必须记录来源、改写者、版权说明和审核状态。
- 神话、历史和名著改编需区分史实、传说与文学情节。

## 7. 核心用户流程

### 7.1 首次收听

1. 儿童在首页点击“故事时间”。
2. 系统根据 `childAge` 展示适龄故事。
3. 儿童点击故事卡片，查看封面、简介、时长和主题。
4. 点击“开始听故事”，音频开始播放。
5. 播放中每 5 秒保存一次内存进度，每 15 秒或页面隐藏时持久化。
6. 实际听过的去重音频区间覆盖总时长 80% 时记为完成；继续播放至结尾。
7. 结束页只提供轻互动：“喜欢”“再听一次”“返回故事屋”。

### 7.2 继续收听

1. 首页优先展示最近一篇未完成的故事。
2. 点击“继续听”后从上次位置前 3 秒恢复，避免断句。
3. 若剩余不足 20 秒，则从最后一个正文段落开始播放。

### 7.3 达到每日时长

1. 播放前计算当天有效收听时长。
2. 达到限制后不自动播放下一篇。
3. 当前故事可以完整播放至结尾；结束后显示“今天的故事时间到啦”，禁止开启下一篇。这是家长确认的 B 方案。
4. 睡眠定时属于主动停止，优先于每日时长规则；跨午夜时按实际播放秒数拆分计入各自然日。

## 8. 儿童端交互要求

### 8.1 故事列表

- 首屏先展示“继续收听”和 4–6 篇适龄推荐。
- 筛选项只保留“阶段、主题、时长”三个维度。
- 故事卡展示封面、标题、时长、阶段和完成状态。
- 已隐藏故事不出现在搜索、推荐和历史的可播放入口中。

### 8.2 播放器

- 主操作按钮触控区域不小于 48×48 像素。
- 默认显示：封面、标题、当前段文字、进度、播放／暂停、前后 15 秒。
- 次级操作：0.8／1.0／1.2 倍速、睡眠定时、收藏。
- 支持 Media Session API 的浏览器提供锁屏播放控制；不支持时正常降级。
- 页面进入后台或锁屏时继续播放，但遵守系统节能及浏览器限制。
- 尊重现有“关闭声音”和“减少动态效果”设置。
- 音频加载失败时保留进度，并显示明确的联网重试入口。

### 8.3 听完反馈

不设置答题门槛。随机展示一个亲子交流提示，例如：

- 你最喜欢哪个角色？
- 如果是你，你会怎么做？
- 把故事讲给家人听一遍吧。

MVP 只记录喜欢和重复收听，不记录答案内容。

## 9. 家长控制

在 `ParentSettings` 中新增故事设置：

```ts
export interface StorySettings {
  enabled: boolean;
  dailyLimitMinutes: 0 | 10 | 20 | 30 | 45 | 60;
  autoplayNext: boolean;
  allowDailyReward: boolean;
  hiddenStoryIds: string[];
  hiddenThemes: StoryTheme[];
}
```

- `dailyLimitMinutes: 0` 表示不限制，不表示关闭故事屋。
- 默认值建议为 20 分钟、关闭自动连播、关闭每日奖励。
- 家长可按单篇或主题隐藏内容。
- 故事设置走现有家长口令保护和家庭云同步。

## 10. 数据结构

故事不复用现有 `ContentItem`。原因是故事包含音频版本、时长、版权审核和播放状态，与每日学习内容生命周期不同。

### 10.1 故事内容

```ts
export type StoryStage = 'kindergarten' | 'primary-lower' | 'primary-upper';

export type StoryTheme =
  | 'bedtime'
  | 'habit'
  | 'emotion'
  | 'safety'
  | 'friendship'
  | 'fable'
  | 'idiom'
  | 'myth'
  | 'history'
  | 'classic'
  | 'science'
  | 'growth';

export interface StoryParagraph {
  id: string;
  text: string;
  startMs?: number;
  endMs?: number;
}

export interface StoryAudioVersion {
  version: string;
  url: string;
  format: 'mp3' | 'wav';
  durationMs: number;
  voice: string;
  generatedAt: string;
}

export interface StoryRights {
  basis: 'original' | 'authorized' | 'public-domain-adaptation';
  sourceTitle?: string;
  sourceAuthor?: string;
  adaptedBy?: string;
  licenseNote: string;
  reviewStatus: 'pending' | 'approved' | 'rejected';
  reviewedAt?: string;
}

export interface Story {
  id: string;
  title: string;
  summary: string;
  stage: StoryStage;
  ageMin: number;
  ageMax: number;
  themes: StoryTheme[];
  estimatedMinutes: number;
  coverUrl: string;
  paragraphs: StoryParagraph[];
  audio: StoryAudioVersion;
  rights: StoryRights;
  status: 'draft' | 'published' | 'archived';
  contentVersion: string;
  updatedAt: string;
}
```

只有 `status === 'published'` 且 `rights.reviewStatus === 'approved'` 的故事可以出现在儿童端。

### 10.2 播放状态

每个孩子、每篇故事只保存一条最新状态：

```ts
export interface StoryProgress {
  id: string;
  storyId: string;
  audioVersion: string;
  positionMs: number;
  durationMs: number;
  listenedMs: number;
  completionCount: number;
  completedAt?: string;
  favorite: boolean;
  startedAt: string;
  lastListenedAt: string;
  updatedAt: string;
}
```

`listenedMs` 只累计实际播放时间；完成判定使用去重的已听区间，不用拖动后的播放位置推算。同一小段反复播放不会使完成比例增长。音频版本变化后保留完成状态，但将恢复位置重置为 0，避免跳到错误段落。

### 10.3 收听事件

```ts
export interface StoryListenEvent {
  id: string;
  storyId: string;
  date: string;
  startedAt: string;
  endedAt: string;
  listenedSeconds: number;
  startPositionMs: number;
  endPositionMs: number;
  completed: boolean;
}
```

事件用于家长历史、每日时长和产品指标。单次播放不足 10 秒不计入有效收听时长，避免误触污染记录。

### 10.4 备份结构调整

内置故事目录随应用版本发布，不进入家庭备份和云快照。在 `AppData` 中仅增加：

```ts
storyProgress: StoryProgress[];
storyListenEvents: StoryListenEvent[];
```

本期保持 `schemaVersion: 1`，新增字段对旧备份可选，恢复时补为空数组；同时更新前端验证、IndexedDB 事务和云备份读写。现有服务端仅接受 V1，同步上限为 5 MB，因此不把故事正文或音频写进快照。收听事件需要按会话汇总，并限制历史规模。

## 11. 音频生成与交付

### 11.1 不采用播放时即时合成长故事

现有 `/api/tts` 适合题目、汉字、古诗和短讲解。长故事若在儿童点击后即时生成，会增加首播等待、超时概率、上游成本和长文本失败风险。

MVP 采用离线预生成：

1. 故事正文审核通过。
2. 为每篇生成整篇音频，并记录段落时间点。
3. 合成结果使用内容哈希和音色生成不可变版本号。
4. 上传至现有 OSS；设置长期不可变缓存。
5. 发布故事记录音频 URL、时长、音色和版本号。
6. 客户端直接播放已生成音频，不占用家庭每日在线朗读额度。

### 11.2 音频接口建议

- 故事目录随应用版本内置。
- 音频必须支持 `Range` 请求，以便拖动和断点续播。
- OSS 或代理接口需配置正确的 `Content-Type`、CORS 和缓存头。
- 文件名使用内容哈希，不在原路径覆盖新音频。
- 音频以支持 `Range` 的静态文件交付；客户端不预缓存全部 40 篇，后续再增加“下载收藏”。

## 12. 完成与奖励规则

- 实际听过的去重区间首次覆盖总时长 80% 时记为完成。
- 拖动进度不增加 `listenedMs`，不能用于判定完成。
- 重复播放增加 `completionCount`，但不会重复发放同一日奖励。
- 默认不发奖励。
- 若家长开启故事奖励：当天首次完整听完一篇获得 1 星光，每天最多一次。
- 故事完成不计入学习日、模块完成数、全勤宝石或间隔复习。

## 13. 异常与边界

- 断网且音频未缓存：展示“这个故事需要联网后首次播放”，不丢失历史进度。
- 音频版本更新：完成状态保留，未完成进度从头开始，并提示“故事声音已更新”。
- 家长隐藏正在播放的故事：当前播放立即停止，返回故事屋。
- 跨设备同时播放：采用 `updatedAt` 较新的进度；收听事件均保留并去重。
- 时钟跨日：有效收听秒数按自然日拆分，午夜后仍允许正在播放的故事听完。
- 删除或下架故事：收听事件保留标题快照，儿童端不可继续播放。
- 浏览器清理缓存：音频可重新下载，云同步的收听记录不受影响。

## 14. 验收标准

### 14.1 功能验收

1. 3–12 岁任一年龄都能看到至少 8 篇适龄故事。
2. 可以按阶段、主题和时长筛选，筛选结果与元数据一致。
3. 播放、暂停、前后 15 秒、倍速和睡眠定时可用。
4. 正常播放期间进度定期保存；退出后再次进入，恢复误差不超过 5 秒。
5. 拖动到结尾不能直接获得完成状态。
6. 实际收听达到 80% 后只记录一次首次完成。
7. 达到家长时长限制后允许当前故事播完，不再自动播放下一篇，也不能手动开启下一篇。
8. 隐藏主题和故事不再出现在儿童端。
9. 家长能查看近 7 天有效收听时长和故事记录。
10. 旧备份恢复后现有学习数据完整，故事字段按迁移规则补齐。

### 14.2 性能与体验验收

- 已缓存音频点击后 1 秒内开始播放。
- 普通网络下音频中位启动时间不超过 3 秒。
- 音频支持拖动后继续加载，不要求完整下载后才能播放。
- 主要按钮满足至少 48×48 像素触控区域。
- 关闭声音时故事入口仍可浏览，但播放前明确提示由家长关闭。
- 减少动态效果开启后，不出现大幅封面缩放和播放动画。

### 14.3 质量验收

- 每篇故事通过正文、适龄性、事实和版权四项审核。
- 中文标点、断句和 TTS 读音抽听无明显错误。
- 所有故事音频 URL 可用，时长与记录误差不超过 2 秒。
- 无未审核故事、空白封面或占位文案进入儿童端。

## 15. 开发拆分建议

### 阶段一：数据与内容

1. 新建故事类型、首批故事 JSON 和校验函数。
2. 增加 IndexedDB 表及备份迁移。
3. 建立故事正文审核和音频预生成脚本。
4. 上传首批音频并验证 Range、缓存和 CORS。

### 阶段二：儿童端

1. 首页故事卡片和 Hash 路由。
2. 故事列表、筛选和详情页。
3. 播放器、进度保存、收藏和睡眠定时。
4. 完成判定、轻反馈和每日时长限制。

### 阶段三：家长端与同步

1. 故事设置和隐藏规则。
2. 收听历史和 7 日汇总。
3. 家庭云备份、恢复和冲突处理。
4. 可选的每日一次奖励。

### 阶段四：验证与发布

1. 单元测试：筛选、完成判定、有效时长、迁移和设置。
2. 浏览器测试：iOS Safari、Android Chrome、PWA 独立模式。
3. 弱网、断网、锁屏、跨日和跨设备测试。
4. 小范围上线，观察启动时间、完整收听率和重复收听率。

## 17. 上线后再评估的方向

只有在 MVP 证明儿童愿意主动听、能够听完并会重复收听之后，再考虑：

- 家长输入孩子昵称生成个性化原创故事。
- 双语故事和中英文切换。
- 角色化多音色配音。
- 收藏故事离线下载。
- 家长录制自己的声音。
- 故事后的开放式表达、复述和亲子任务。
- 将少量成语、历史故事关联到现有学习模块，但仍不强制进入每日任务。

## 18. 当前实现与发布前待办

2026-09-24 的本地实现已包含独立故事屋、40 篇中文故事、分龄和主题筛选、播放器、进度保存、收藏、睡眠定时、家长设置和收听历史。40 篇长版扩写稿已生成并单独保存，也均已制作长版音频与逐句时间点。前 3 篇使用千问 `qwen-audio-3.0-tts-flash` 与 `longanhuan_v3.6`，后 37 篇使用 `qwen-audio-3.1-tts-flash` 与对应的 `longanhuan_v3.1` 音色；所有故事均按句切片并使用适度的情绪标签。播放器随播放、拖动、续听和倍速切换高亮句子。录音作为应用静态文件发布，支持 HTTP Range；暂未迁移至 OSS。

批量配音期间 3.0 模型返回 `AllocationQuota.FreeTierOnly`。经用户确认后，将模型与兼容音色一起切至 3.1，并已成功完成后续 37 篇；没有关闭账号的付费保护。6 篇较短成片经过安全范围内的保音高变速（播放速度调整不超过 16%）并重新校准逐句时间点，原始录音保留在本地制作缓存中。全量发布脚本已核对 40 篇音频文件、正文一致性、逐句时间连续性与各阶段目标时长。此结果是自动校验，不等同于人工听审。

正式对外发布前仍需：

1. 逐篇进行人工试听校对，尤其检查模型误读、漏读、语气不当和变速后听感；外部文本服务只在用户明确授权下调用。
2. 对每篇故事记录来源、改写者、音频制作方式及审核结果，完成适龄性、事实和版权审核。
3. 在实际设备上检查长版的逐句高亮效果；时间点来自音频切片时长，不是字级别强制对齐。
4. 评估 OSS 交付、浏览器离线缓存和真实手机锁屏播放。当前静态 MP3 可在线拖动，离线播放不作保证。
5. 按第 14 节验收清单完成 iOS Safari、Android Chrome 与 PWA 独立模式验证，再对外发布。
