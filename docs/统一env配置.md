# 统一使用 .env

应用、数据库连接、会话密钥、大模型、语音、OSS、限额与部署镜像/宿主端口都放在项目或服务器部署目录的 `.env`。配置模板仅保留根目录 `.env.example`，不要用模板覆盖已有私有文件。

## 读取方式

- 开发和预览由 `server/environment.mjs` 读取当前目录的 `.env`，关闭Vite默认的模式/`.env.local`加载。
- 应用和操作脚本启动时读取同一个文件；不需要另外准备运行时或语音配置。
- Docker应用将宿主 `.env` 只读挂载到 `/app/.env`，用Node原生dotenv解析；不把所有配置当作Compose插值变量注入应用，避免密钥中的`$`等字符被意外展开。容器内部端口固定80，宿主端口由 `.env` 的 `LEXUE_PORT` 设置。缓存目录也从同一个文件注入，以覆盖旧镜像内置默认值并保障回滚。
- 两种PostgreSQL Compose方案均从同目录 `.env` 获取 `POSTGRES_DB`、`POSTGRES_USER`、`POSTGRES_PASSWORD`。使用容器数据库时，显式设置 `DATABASE_URL` 指向 `postgres:5432`（单独数据库方案为实际容器内网地址），连接串密码必须URL编码，生产设置 `DATABASE_REQUIRED=true`。
- 宿主/CI注入的环境变量优先，用于容器内部端口和测试参数；应用的私有配置文件只有 `.env`，GitHub SSH登录凭据仍由平台Secrets管理。

配置改动后重启开发/预览服务；生产执行 `docker compose up -d --force-recreate lexue`。文件只读挂载不能代替重建容器，因为原子更新会替换文件节点。

## 旧配置的一次性迁移

本地项目已经迁移，旧 `.env.local` 已备份并移除。备份在被Git/Docker忽略的 `.env.backups/`，目录权限700，备份和新 `.env` 权限600。正常运行不读取备份。

服务器尚未执行迁移。新自动发布会在校验和离线构建成功后、切换应用前自动迁移。也可提前把 `deploy/env-config.mjs` 复制到服务器部署目录，使用已有Node环境迁移：

```sh
# 服务器已有Node 22时；命令在部署目录执行
node env-config.mjs migrate .
# 或用已经缓存的项目Node运行环境镜像，不需服务器安装Node
# 将镜像名替换为实际已缓存镜像
docker run --rm --network none --user "$(id -u):$(id -g)" \
  -v "$PWD:/config" -w /config --entrypoint node \
  已缓存的运行环境镜像 env-config.mjs migrate /config
```

新运行环境镜像已去除写死的缓存目录，环境标识会随之改变，因此首次发布可能需要重新上传一次运行环境镜像。

迁移顺序为现有 `.env` → 旧运行时配置 → 旧语音配置 → 旧PostgreSQL配置 → 旧本地覆盖配置；后面的同名值优先，延续原运行方式。生产目录一般没有本地覆盖文件。迁移只输出覆盖的变量名和备份位置，不输出值；先校验是否能无损表示，再备份原文件、原子写入 `.env`，最后移除旧文件。遇到不能同时兼容Node/Compose的特殊引号组合会拒绝迁移，原文件保留，不会截断或默默改写密钥。

已经统一为 `.env` 的目录不用继续维护旧文件，也不要重新创建它们。检查配置可使用只显示变量名的方式，不要把私有文件内容或完整 `docker compose config` 输出公开。

## 发布与回滚

`remote-deploy.sh`调用随发布上传的`env-config.mjs`，更新 `LEXUE_IMAGE`，保留 `.env` 里的宿主端口 `LEXUE_PORT` 和其他所有值；手动明确传入端口时才更新端口。每次更新前备份，发布失败回滚时仍只改这两项，不丢失密钥和限额。新Compose启动命令包含 `--env-file=/app/.env`，回滚到尚未包含统一加载模块的旧Node镜像也能读取配置。

应用包仍采用白名单打包，`.env` 与备份不进入应用归档、Docker镜像或Git仓库。历史安全审计报告中的旧文件名仅用于记录当时证据。
