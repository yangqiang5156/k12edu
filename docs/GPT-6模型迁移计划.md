# GPT-6 模型迁移计划

制定日期：2026-09-27。范围为家长中心的两项**文本生成**能力；这是一份实施计划，当前没有更改线上模型或调用代码。

## 1. 现状与目标

| 场景 | 当前实现 | 建议候选 | 选择依据 |
| --- | --- | --- | --- |
| “一句话新增资料” | `server/content-generator.mjs` 调用 DeepSeek Chat Completions，返回 JSON，校验失败最多再请求一次 | `gpt-6-luna`，从 `reasoning.effort: "low"` 起测 | 输入短、输出字段固定、调用频率可能较高；先检验准确率与低成本 |
| 家庭故事草稿 | `server/story-service.mjs` 调用同一 DeepSeek 模型，生成 3/5/8 分钟中文故事 | `gpt-6-sol`，从 `reasoning.effort: "medium"` 起测；`gpt-6-astra` 作为质量对照 | 长文需要适龄性、情节连贯、原创性和较稳定的篇幅 |
| 在线朗读与故事配音 | `server/tts.mjs` 使用千问、豆包或 MiniMax TTS | 本轮保持现有配置 | 与上述文本生成分离；现有音频缓存和录音版本不应受文本模型切换影响 |

最终选择以本项目的评测结果为准，不预设必须使用最强模型。若 Luna 的资料准确性未达标，升级该场景至 Sol；若 Sol 的故事质量未达标，再评估 Astra。两项场景分别配置模型，避免共用一个默认值。OpenAI 官方将 Luna 定位为高效的限定任务模型、Sol 定位为需要判断的日常工作模型、Astra 定位为高难任务模型：[模型选择](https://developers.openai.com/api/docs/guides/model-selection)、[GPT-6 指南](https://developers.openai.com/api/docs/guides/latest-model)。

## 2. 实施顺序

### 阶段 A：建立基线和评测集

1. 从已有测试和真实使用类型中整理匿名评测集。资料生成至少覆盖六个模块、选择题答案校验、古诗/作者、科学事实、外部链接约束、年龄边界与不完整输入；故事至少覆盖 3/5/8 分钟、3–6/7–9/10–12 岁、各类主题、昵称开关和不适合儿童的主题。不要把真实儿童姓名或家庭资料写入评测文件。
2. 用当前 DeepSeek 路径记录首轮有效率、重试后有效率、家长需要修改的比例、故事篇幅达标率、适龄与安全问题、端到端耗时、每次成功生成的实际费用。人工抽检故事的情节、重复、事实、价值导向和原创性风险。
3. 固定评分办法及通过阈值，然后用同一输入比较 Luna、Sol、Astra。建议上线门槛：资料结构校验通过率至少 99%，数学答案错误为 0；故事结构校验通过率至少 98%，严重儿童安全问题为 0；其余质量、延迟、成本指标以现网基线为参照，由评测结果决定取舍。这些是**建议验收线**，需用实际样本规模和基线校准。

### 阶段 B：增加 OpenAI 服务端适配层

1. 在服务端新增独立适配层，使用 Responses API；服务端环境变量增加 `OPENAI_API_KEY`、资料模型和故事模型配置。密钥只在服务端读取，不增加 `VITE_` 变量。保留当前 DeepSeek 实现作回滚开关，且不改历史数据或旧故事音频。
2. 为两个场景分别定义严格的结构化输出契约，并继续调用现有 `validateGeneratedContent`、`validateStoryDraft` 作最终业务校验。将 Responses 输出、拒答/截断和错误码转换为现有前端能处理的结果；只对可修复的内容校验错误重试，限制尝试次数和总耗时。
3. 保留当前的额度、并发、跨站请求限制和家长确认流程。资料仍先进入编辑表单；故事仍须家长检查、保存、试听并手动发布。昵称仅在家长主动开启时传给模型，不发送不必要的孩子资料。
4. 从 DeepSeek 请求中迁出 `thinking`、`temperature`、`max_tokens` 等供应商或旧接口字段。GPT-6 使用 `reasoning.effort` 和 Responses 对应的输出上限；有推理时不得继续带 `temperature`、`top_p`、`top_logprobs`。读取 Responses 的 `usage` 后，分别记录输入、输出、推理和缓存相关用量，避免继续用单一 `AI_MILLION_TOKEN_ESTIMATED_COST` 误估费用。参见 [官方迁移说明](https://developers.openai.com/api/docs/guides/latest-model)。
5. 修改 `.env.example`、README、家长界面的供应商提示，以及依赖 DeepSeek 请求格式的测试。优先保持当前对外 API 路径和返回结构，减少前端改动。

### 阶段 C：验证与灰度

1. 用模拟上游响应验证请求参数、结构化输出解析、截断/拒答/429/超时处理、校验反馈重试、用量记账和回滚开关；运行 `pnpm test`、`pnpm build`。再用已授权的测试密钥做少量真实请求，确认账户可访问目标模型、服务端能连通 API，以及实际耗时和账单。
2. 按“内部账号 → 少量家庭 → 全量”逐步放量。分别观察两项场景的成功率、人工修改率、P95 延迟、每次成功生成费用、超时和重试次数；每一阶段至少覆盖所有故事长度与主要资料类型。
3. 任一场景单独回退至原提供商和模型，不回退数据库、不删除新草稿；已保存的家庭故事与现有 TTS 任务继续可用。若接入条件、费用上限或质量门槛未满足，保持该场景在原路径，并记录具体阻塞项。

## 3. 关键文件与边界

- 服务端调用：`server/content-generator.mjs`、`server/story-service.mjs`。
- 用量和费用：`server/usage.mjs`、`server/identity.mjs`，以及对应数据库统计字段；先确定新旧供应商是否需要分列，再调整管理后台展示。
- 前端提示：`src/components/ContentLibraryManager.tsx`；家庭故事界面应继续表达“生成后由家长检查”。
- 配置和说明：`.env.example`、`README.md`、相关部署文档。
- 本轮不改：`server/tts.mjs`、音频缓存键、40 篇内置故事音频、家庭故事历史记录。

## 4. 决策和上线条件

首先比较 **Luna 生成资料 / Sol 生成故事** 与现网基线。若质量线通过，选择每次成功生成成本更低、延迟可接受的组合；若未通过，按场景上调至 Sol 或 Astra，而不是整体切换。上线前还需确认 OpenAI 账户的模型权限、付款与预算、部署服务器的网络连通性，以及儿童信息处理要求；这些条件不能仅凭代码仓库确认。

费用按实际输入、缓存写入/读取、输出和重试计算，并以正式账单核对。官方当前价格与能力以 [定价页](https://developers.openai.com/api/docs/pricing) 和各模型页面为准；模型选择应以同一批真实任务的成功率、延迟和每次成功成本验证：[部署检查表](https://developers.openai.com/api/docs/guides/deployment-checklist)。
